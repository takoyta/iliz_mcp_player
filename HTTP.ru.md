# HTTP-протокол управления

## MCP (Streamable HTTP)

Пока плеер работает:

`http://127.0.0.1:17321/mcp`

JSON-RPC поверх Streamable HTTP (тот же loopback-сервер, что и REST). Cursor / Claude / Inspector:

```json
{
  "mcpServers": {
    "iliz-player": {
      "url": "http://127.0.0.1:17321/mcp"
    }
  }
}
```

Инструменты совпадают с REST. `play` предпочитает `id`. Ошибки инструментов — `isError` и те же строки `error`, что у REST.

| Инструмент | Аргументы | Описание |
| --- | --- | --- |
| `search` | `query` | Ищет по названию, исполнителю, альбому или имени файла. Пустой запрос — очередь (не больше 50). `id` нужен для play. |
| `now` | — | Текущий трек: состояние (playing, paused, stopped), название, исполнитель, позиция. Воспроизведение не меняет. |
| `play` | `id`, `query` | Включает трек. `id` важнее; `query` берёт первый найденный. Это не пауза. |
| `skip` | `dir` | Следующий или предыдущий в очереди. `dir`: next (по умолчанию) или prev. При перемешивании следующий — случайный. Предыдущий, если прошло больше 3 с, начинает текущий сначала. |
| `like` | `id`, `liked` | Лайк или снятие. Без `id` — загруженный трек. `liked` 1 или 0 задаёт явно; без него — переключает. |
| `stop` | — | Стоп и сброс текущего трека. Это не пауза. |

---

Локальный JSON API для агентов. Доступен, пока плеер работает.

- Базовый URL: `http://127.0.0.1:17321`
- Слушает только loopback
- `--port N` — слушать этот порт и не проверять единственный экземпляр (для тестов)
- Методы: `GET` или `POST` (важна строка запроса)
- Ответ: `Content-Type: application/json; charset=utf-8`

Поиск смотрит **название, исполнителя, альбом и имя файла**. Учитываются префикс и подстрока (`oxw` / `oxwave`), ранжирование FTS5, транслит (`meteor` / `метеор`), русское написание на слух (`оксвэйв` / `oxwave`) и опечатки (`mrteor`, расстояние 1–2). Поле поиска в окне не меняется.

`id` трека — идентификатор в базе (стабилен, пока строка существует).

Очередь лежит в `%APPDATA%\iliz\iliz_mcp_player\library.db`. Лайк и число прослушиваний — поля трека. Если убрать лайкнутый трек из очереди, строка в базе остаётся.

## Эндпоинты

### `GET /search?q=`

Найти треки. Пустой `q` возвращает плейлист (с ограничением).

```
GET /search?q=love
```

```json
{
  "ok": true,
  "query": "love",
  "count": 2,
  "returned": 2,
  "tracks": [
    {
      "id": 4,
      "title": "love.mp3",
      "path": "C:\\Music\\love.mp3",
      "artist": "",
      "album": "",
      "liked": 0,
      "plays": 0,
      "duration": 183
    }
  ]
}
```

- `count` — сколько совпало
- `returned` — сколько элементов в `tracks` (не больше 50)
- `duration` — секунды, или `0`, если длительность ещё не прочитана
- `liked` — 0 или 1
- `plays` — сколько раз трек запускали

### `GET /play?id=`

Включить трек по `id` из поиска (или из плейлиста).

```
GET /play?id=4
```

```json
{
  "ok": true,
  "id": 4,
  "title": "love.mp3",
  "liked": 0,
  "plays": 1,
  "path": "C:\\Music\\love.mp3"
}
```

Или первый результат поиска:

```
GET /play?q=love
```

Если заданы и `id`, и `q`, побеждает `id`.

### `GET /now`

Текущее воспроизведение. `state`: `playing`, `paused` или `stopped`. Если ничего не загружено, полей трека нет.

```
GET /now
```

```json
{
  "ok": true,
  "state": "playing",
  "shuffle": 0,
  "position": 12,
  "id": 4,
  "title": "love.mp3",
  "artist": "",
  "album": "",
  "liked": 0,
  "plays": 1,
  "duration": 183,
  "path": "C:\\Music\\love.mp3"
}
```

- `position` — секунды от начала трека
- `shuffle` — 1, если случайный следующий включён (та же кнопка, что в окне)

### `GET /skip`

Следующий или предыдущий трек (как кнопки плеера). `dir`: `next` или `prev`; без параметра — следующий. С перемешиванием следующий — случайный другой трек очереди, не `i+1`. Без перемешивания следующий идёт по очереди по кругу. Предыдущий начинает текущий сначала, если прошло больше 3 секунд.

```
GET /skip
GET /skip?dir=next
GET /skip?dir=prev
```

```json
{
  "ok": true,
  "dir": "next",
  "shuffle": 1,
  "id": 5,
  "title": "love_song.mp3",
  "liked": 0
}
```

### `GET /like?id=`

Переключить лайк. Без `id` — текущий трек. `liked=0` или `liked=1` задаёт значение вместо переключения.

```
GET /like?id=4
GET /like?id=4&liked=1
GET /like
```

```json
{ "ok": true, "id": 4, "liked": 1, "title": "love.mp3" }
```

### `GET /stop`

Остановить воспроизведение (не пауза). Текущий трек сбрасывается.

```
GET /stop
```

```json
{ "ok": true }
```

## Ошибки

Неизвестный путь — HTTP 404. Остальные сбои — HTTP 200 и `"ok": false`.

```json
{ "ok": false, "error": "no match" }
```

| `error` | Когда |
| --- | --- |
| `unknown endpoint` | путь не `/search`, `/play`, `/now`, `/skip`, `/like`, `/stop` |
| `id or q required` | `/play` без `id` и без `q` |
| `no match` | `/play?q=` ничего не нашёл, или неизвестный `/like?id=` |
| `nothing playing` | `/like` без `id`, и ничего не загружено |
| `bad dir` | `/skip?dir=` не `next` и не `prev` |
| `cannot play` | файла нет или формат не поддерживается |
| `player not ready` | окно занято или плеер закрывается |

## Примеры

```bat
curl "http://127.0.0.1:17321/search?q=love"
curl "http://127.0.0.1:17321/play?id=4"
curl "http://127.0.0.1:17321/now"
curl "http://127.0.0.1:17321/like?id=4&liked=1"
curl "http://127.0.0.1:17321/play?q=love"
curl "http://127.0.0.1:17321/skip?dir=next"
curl "http://127.0.0.1:17321/stop"
```

UTF-8 в `q` нужно передавать в URL-кодировке.

Обычный ход агента: `/now` или `/search` → выбрать `id` → `/play?id=` → `/skip?dir=next` → `/like?liked=1` → `/stop`, когда закончил.
